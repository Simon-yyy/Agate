# 核心协同与安全规范 (Agate / Agent Gate)

## 1. 中文原生与代码完整性
- 交互思考、排查分析、代码注释与 Git Commit Message 必须使用规范简体中文；技术术语与代码标识符保留原样。
- 改动代码必须完整可运行，严禁偷懒使用 `// ... 保持不变` 等伪代码占位符。

## 2. 两阶段硬门禁 (Two-Phase Gate)
- 遇到任何排查、探查、修复或业务修改任务，首轮仅输出根因分析、精简方案与拟改动文件清单，严禁直接改动代码。
- 必须停步显式提示：“👉 请确认方案，确认请回复‘执行’”，严格等待用户明确回复后方可在下一轮动手落盘。
- 豁免项：收到“完善/初始化 MAP.md 与 contexts/context.md”冷启动指令时，按协议直接扫描并填充落盘。

## 3. 寻路规范 (3-Hop Navigation)
- 寻路顺序严格遵循：MAP.md (架构地图) -> contexts/context.md (技术契约) -> 目标源码。严禁全仓盲扫。
- 文档泛化维护指令仅限变更此两份地图文件，严禁篡改业务自身的 README.md 或外部文档。

## 4. 闭环验证与两振熔断 (Fail-Fast)
- 代码落盘后，必须主动在终端调用 `agent-verify`（或 `agate verify`）自检，拿到绿色 `[PASS]` 物证后方可交付。
- 同一错误若连续修复 2 次未果，必须强制触发熔断（`IsFinal=true`）停止盲试，向用户移交主控权并输出错误堆栈。

## 5. 绝对安全红线与动作外溢公理 (The Explicit Mandate Rule)
- **动作二分与外溢死锁**：
  - **本地闭环动作**（读取检索、代码编辑、本地编译、单测运行、`agent-verify` 自检）：常规任务或方案确认后即可执行；
  - **外溢与状态跃迁动作**（Git 提交/推送/标签、Release 附件上传、包管理器发布、CI/CD 触发、部署推流、数据库 DDL/DML 变更、破坏性删除）：**默认 100% 处于绝对死锁状态**！
- **显式授权排他性（指哪打哪，严禁顺带）**：
  - 常规方案确认（如“执行”、“确认”、“好的”）的授权范围**严格且仅限本地闭环动作**，严禁以“顺便完成”、“自动化闭环”为由越权代跑外溢动作！
  - **唯有且仅当用户在当前指令中给出明确指向该动作的专属动词（如“提交代码”、“推送到远程”、“上传Release”、“发布到NPM”）时，该特定外溢动作才被单次解锁代跑**；未见字面明确指令，外溢操作绝对禁止执行！
  - **授权凭证注入契约**：在获得用户显式“推送/上传”指令后代跑时，Agent 须声明 `ALLOW_AUTOMATED_PUSH=1` 环境变量通过底层 pre-push 物理卡口进入 `agate verify` 自检；未见指令时严禁声明该凭证或调用 push 命令！
- **隐私防线与破坏预警**：严禁在代码、日志或回复中回显任何 API Key、密码与私钥明文；涉及破坏性操作前必须显式预警并等待二次确认。

## 6. 跨 Agent 任务接力协议 (Relay Protocol)
- **唤醒接力契约**：在跨会话或切换 Agent 工具（如从 Antigravity 切换到 Cursor）唤醒时，Agent 必须先执行 `agate task resume` 或检视 `TASK.md`，精确继承前任在“接力四要素”中留下的断点与下一步建议，杜绝盲目重构。
- **交接流转契约**：切换工具或阶段交付前，必须执行 `agate task handover` 触发自动化门禁自检与自包含 HTML 审查物证生成，确保交接单（`TASK.md`）状态流转为 `HANDOVER_READY` 后方可离场。
- **终态归档契约**：任务最终交付时，必须执行 `agate task done` 执行全量门禁自检，将 `TASK.md` 状态流转为 `[DONE]` 终态并解绑释放租约互斥锁。

## 7. 记忆资产神圣公理与防泛化防线 (Memory Governance Rule)
- **长期记忆只读与越权封锁**：`MEMORY.md` 是人类工程师沉淀的全局长期架构事实与避坑禁忌库，Agent **默认严格只读，绝对严禁私自直写**！
- **临时暗坑绝不泛化**：单次排查中遇到的偶发报错、临时网络波动或特定环境状态，**必须且仅能写入当期 `TASK.md` 的“暗坑警示”中**，随任务生命周期归档自然消亡，严禁泛化为全局铁律！
- **提议制准入与显式授权**：若 Agent 发现具备全局价值的重大系统性暗坑，仅可在回复中发起提议（*“💡 发现通用避坑规律，是否写入 MEMORY.md？”*）；唯有获得用户明确指令（如“写入记忆”、“确认固化”）时，方可单次追加写入。
