# Agate (Agent Gate) 协议与规范标准手册

## 一、 AI 协同规约标准模板 (SKILL.md / SSOT)

各 Agent 工具共享的核心协同规约如下，此文件作为全局单一事实源：

```markdown
# 核心协同与安全规范 (Agate / Agent Gate)

## 1. 中文原生与代码完整性
- 交互思考、排查分析、代码注释与 Git Commit Message 必须使用规范简体中文；技术标识符与路径保留原样。
- 改动代码必须完整可运行，严禁偷懒使用 `// ... 保持不变` 等伪代码占位符。

## 2. 两阶段硬门禁 (Two-Phase Gate)
- 遇到任何排查、探查、修复或业务修改任务，首轮仅输出根因分析、精简方案与拟改动文件清单，严禁直接改动代码。
- 必须停步显式提示：“👉 请确认方案，确认请回复‘执行’”，严格等待用户明确回复后方可在下一轮动手落盘。
- 豁免项：收到“完善/初始化 AGENTS.md 与 contexts/context.md”冷启动指令时，按协议直接扫描并填充落盘。

## 3. 寻路规范 (3-Hop Navigation)
- 寻路顺序严格遵循：AGENTS.md (架构地图) -> contexts/context.md (技术契约) -> 目标源码。严禁全仓盲扫。
- 文档泛化维护指令仅限变更此两份地图文件，严禁篡改业务自身的 README.md 或外部文档。

## 4. 闭环验证与两振熔断 (Fail-Fast)
- 代码落盘后，必须主动在终端调用 `agent-verify`（或 `agate verify`）自检，拿到绿色 `[PASS]` 物证后方可交付。
- 同一错误若连续修复 2 次未果，必须强制触发熔断（`IsFinal=true`）停止盲试，向用户移交主控权并输出错误堆栈。

## 5. 绝对安全红线与动作外溢公理 (The Explicit Mandate Rule)
- **动作二分与外溢死锁**：
  - **本地闭环动作**（读取检索、代码编辑、本地编译、单测运行、`agent-verify` 自检）：常规任务或方案确认后即可执行；
  - **外溢与状态跃迁动作**（Git 提交/推送/标签、Release 附件上传、包管理器发布、CI/CD 触发、部署推流、数据库 DDL/DML 变更、破坏性删除）：**默认 100% 处于绝对死锁状态**！
- **显式授权排他性（指哪打哪，严禁顺带）**：
  - 常规方案确认（如“执行”、“确认”、“好的”）的授权范围**严格且仅限本地闭环动作**，严禁以“顺便完成”、“自动化闭环”为由越权代跑外溢动作！
  - **唯有且仅当用户在当前指令中给出明确指向该动作的专属动词（如“提交代码”、“推送到远程”、“上传Release”、“发布到NPM”）时，该特定外溢动作才被单次解锁代跑**；未见字面明确指令，外溢操作绝对禁止执行！
- **隐私防线与破坏预警**：严禁在代码、日志或回复中回显任何 API Key、密码与私钥明文；涉及破坏性操作前必须显式预警并等待二次确认。
```

## 二、 隐形隔离名单标准规范

执行 `agate isolate` 或 `agate init` 时，系统会自动将以下清单写入本地 `.git/info/exclude`，静默忽略 AI 专有文件：

```text
# --- agate private tracking start ---
.gemini/
.agents/
.ai-memory/
.cursorrules
.windsurfrules
CLAUDE.md
TASK.md
MEMORY.md
.ignore
.vscode/
*.log
logs/
# --- agate private tracking end ---
```

### 隔离原则与幂等性保证 (M5 规范)
1. **公共共享资产（进入 Git 跟踪）**：
   - `AGENTS.md`：项目架构与模块拓扑地图（供所有人及 AI 共享）；
   - `contexts/context.md`：团队约定的技术契约与运行约束。
2. **私有状态资产（本地排除）**：
   - 个人 AI 会话记录、Memory 记忆卡片、临时 Task 进度追踪等。
3. **幂等性与零污染契约**：
   - **块级防破坏追加**：写入 `.git/info/exclude` 时必须使用包含标记符（`# --- agate private tracking start ---` 与 `# --- agate private tracking end ---`）的专用块，绝不覆写用户原有的排除配置；
   - **完全本地生效**：`.git/info/exclude` 仅在开发者本地 `.git` 目录生效，不进版本库，不修改项目公共 `.gitignore`，杜绝协同 Diff 噪音。

## 三、 Git Hook 门禁安装与防篡改策略 (M4 规范)

### 3.1 拦截阶段与职责
- **`pre-commit` 门禁**：在提交暂存区代码前强制调用 `agate verify`（Phase 0 前置红线审计与测试），防止脏代码、绝对路径或私有配置被 Git 提交；
- **`pre-push` 物理阻断**：严格阻止 AI 在未经用户指令时执行 `git push` 偷跑代码至远端。

### 3.2 Hook 安装与防篡改策略
1. **非破坏性备份**：若检测到开发者已有同名 Hook，必须自动重命名备份（如 `pre-commit.agate.bak`），严禁静默覆盖；
2. **标记行识别**：写入的脚本必须带有 `# --- agate hook: <type> ---` 专用标识行；
3. **精准清理还原**：在执行卸载或移除时，仅精准移除由 agate 管理的钩子并还原原备份脚本。

## 五、 退出码与物证协议标准 (L1 规范)

### 5.1 CLI 退出码契约（Exit Codes）
作为可被 CI、Git Hook 及自动化 Agent 调用的标准化工具，明确如下三态退出码：
| 退出码 | 标识 | 语义 | AI 与 CI 处理策略 |
| :--- | :--- | :--- | :--- |
| **`0`** | `[PASS]` | 验证全部通过，安全合规且测试绿灯 | 准予提交或交工，向用户呈现通过物证 |
| **`1`** | `[FAIL]` | 触发安全红线拦截、编译失败或单测报错 | 阻断提交，触发诊断修复；若连续第 2 次为 1，立即触发两振熔断 |
| **`2`** | `[USAGE_ERR]` | CLI 命令参数解析错误或运行时内部异常 | 阻断流程，检查命令调用传参合法性 |

### 5.2 交付物证格式
Agent 向用户交付时，聊天框必须包含类似下述格式的实机物证回显：
```text
=== [agate verify] 闭环自检完成 ===
[PASS] 本地交付物校验通过，结构完备 (耗时: 264ms)
所有修改符合门禁要求，已具备交付条件。
```
